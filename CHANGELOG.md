## 2026-07-02 — Аудит безпеки Fable 5 + виправлення (7 знахідок)

Глибокий аудит коду (модель Fable 5) + прогін через код-критик (панель GLM/Qwen/DeepSeek/GPT-5.3).
Бекенд-хуки тепер під контролем версій у цьому репо: `pb_hooks/`, `pb_migrations/`.

- **[backend] CRITICAL — таємне голосування знову таємне.** Правило `votes` було «будь-який
  учасник групи читає всі голоси» → через прямий API можна було деанонімізувати таємний бюлетень.
  Тепер `listRule/viewRule = user = @request.auth.id` (тільки свій голос). Поіменний список
  відкритих голосувань і підсумки — через серверні маршрути. Новий `POST /api/spilka/voting-ballots`
  (таємне → лише свій рядок). `voting-results` більше не віддає лічильник активного таємного.
  Міграція `pb_migrations/1782996239_security_rules_votes_history.js`.
- **[backend] HIGH — цілісність електорату.** Хук голосу відхиляє тих, хто вступив ПІСЛЯ старту
  голосування (`joined_after_voting_started`), щоб склад голосуючих збігався зі знімком кворуму —
  інакше адмін міг додати нових учасників посеред голосування й «пропхати» результат.
- **[backend] MEDIUM — витік ПІБ.** `submit-join` / `request-role-change` більше не повертають
  ім'я жильця у помилці «квартира зайнята» (не-члену). Адмінський маршрут — без змін.
- **[backend] MEDIUM — group_history** тепер читається лише в межах своєї групи (було: будь-який
  залогінений бачив історію всіх груп).
- **[backend] LOW — заморожений учасник** більше не може створювати голосування (`excluded_cannot_create`).
- **[frontend] MEDIUM — service worker** більше не кешує приватні відповіді PocketBase
  (`/api/…` → лише мережа); logout чистить Cache Storage. SW bump `spilka-v42`.
- **[frontend]** `getVotingVotes` читає через новий маршрут; повідомлення про помилки локалізовані
  (uk/en/ru), стійкі до нової форми `apartment_taken` без імені.

Бекап перед деплоєм: `/opt/spilka-backups/pre-security-20260702_124721`. Деплой перевірено:
міграція застосована, правила у БД змінені, маршрути відповідають, health 200.

## 2026-06-29

### «Заморозка (BETA)» → «Виключення з підрахунку»
Повне переосмислення й побудова заново. Мета: прибрати «мертві душі» (продана квартира,
людина виїхала чи не бере участі) зі знаменника кворуму, щоб % участі та більшість були реальні.
- **[backend]** Раніше в PocketBase логіки заморозки не було взагалі (поля є, коду 0) — написано з нуля.
  Окремий шлях завершення (без «За/Проти»): якщо за 5 днів <2 різних заперечень → виключення застосовується.
- **[backend]** Миттєве скасування: 2 різних «Не згоден» АБО заперечення самого цільового учасника.
- **[backend]** Знімок кворуму на кожне голосування (`voter_snapshot`) — пізні виключення не міняють уже
  запущені голосування. Виключений не рахується у кворумі й не може голосувати.
- **[backend]** Запобіжник: не можна виключити так, щоб активних лишилось <2. Новий власник квартири
  автоматично прибирає «привида» (+ індекс `idx_voter_apartment` враховує `is_frozen`). Анти-дубль:
  не можна 2-е активне предложення по тому самому учаснику. Унікальність заперечень (voting,user).
- **[frontend]** Кнопка «Я тут» — виключений повертає себе будь-коли; адмін теж може повернути вручну.
  Фіксоване вікно 5 днів. i18n UK/EN/RU переписано + інструкція оновлена. SW v40.
- Тести: 28/28 серверних сценаріїв. Пам'ять: `freeze-exclude-redesign`.

### Друкований протокол голосування

  місце для підписів. i18n UK/EN/RU + новий пункт в інструкції («Експорт даних»). SW v41.

### Інше
- **[frontend]** Прибрано банер «⚠️ Сайт у розробці» з екрана входу — ядро працює і живе.
- **Діагностика «не створюється голосування / крутиться кружок»:** причина — стара версія застосунку
  в кеші браузера (старий service worker). Поточний код перевірено вживу — створення працює (адаптер
  ~22мс, реальний клік «Створити» ~200мс). Захист уже вбудований: network-first для коду, nginx no-cache,
  авто-перезавантаження при новій версії (`controllerchange`). Разовий Ctrl+Shift+R переводить на свіжу версію.
